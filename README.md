# System24 Windows dots

Configuration files for a Windows desktop built around Komorebi, WHKD, YASB, and Matugen.

## Layout

- `komorebi/` - Komorebi configuration and optional application rules.
- `whkd/` - WHKD keybindings.
- `yasb/` - YASB bar configuration, styling, generated palette, and the Matugen bridge script.
- `matugen/` - Matugen configuration.
- `install.ps1` - Installs the files and resolves the current user's wallpaper path.
- `fastfetch/` - Compact Fastfetch configuration and custom System24 ASCII logo.

## Active color pipeline

1. The YASB wallpaper widget selects an image.
2. `yasb/update-matugen.ps1` runs Matugen with that image.
3. Matugen reads `yasb/matugen-yasb.css`.
4. Matugen writes `yasb/palette.css`.
5. Matugen reads `komorebi/komorebi-matugen.json`.
6. Matugen writes the generated Komorebi config to `%USERPROFILE%\komorebi.json`.
7. `yasb/styles.css` imports `palette.css`, and the wallpaper script reloads Komorebi after generation.

Komorebi uses `border_colours` (British spelling) and `border_style`. The `theme` block is intentionally omitted because Komorebi documents that defining a theme disables `border_colours`. `border_implementation` must use a value supported by the installed Komorebi version; this setup uses `Komorebi`.

## Komorebi application rules

`komorebi/komorebi.json` works without `applications.json` for the core tiling setup. The main configuration references `%USERPROFILE%/applications.json` as an optional app-specific rules file. You can omit it, create your own, or copy only the entries for applications you use into your own `applications.json`.

## YASB system colors

`yasb/yasb_colors.css` is generated by YASB when `system_colors: true` is enabled. It contains Windows accent/background/foreground variables. The active wallpaper color pipeline is Matugen -> `yasb/palette.css`; `yasb_colors.css` is retained for YASB compatibility and any styles that use its `--yasb-*` variables.

## Files intentionally not tracked

Runtime logs such as `yasb.log` and `matugen.log` are ignored. The removed Windhawk configuration is not part of this repository. Wallust files are also excluded because Matugen is the active color generator.

## Installation notes

### Fastfetch

The Fastfetch setup is installed to `%USERPROFILE%\.config\fastfetch`. It uses the
custom `logo.txt` artwork and keeps the output intentionally compact: identity,
OS, host, kernel, uptime, window manager, CPU, GPU, memory, disk, shell, and
terminal. The logo uses the requested ANSI color mapping `3 5 1` through
Fastfetch's `$1`, `$2`, and `$3` placeholders.

Run `fastfetch` normally after installation. To preview the repository config
without installing it, replace `__FASTFETCH_DIR__` with the target directory or
run the installer.

- Copy `komorebi/komorebi.json` to `%USERPROFILE%`. `applications.json` is optional; copy it to `%USERPROFILE%` only if you want these app-specific rules, or create your own file there.
- Copy `whkd/whkdrc` to `%USERPROFILE%\.config\whkdrc`.
- Copy the contents of `yasb/` to `%USERPROFILE%\.config\yasb`.
- Copy `matugen/config.toml` to `%APPDATA%\matugen\config.toml`.
- Put wallpapers in `%USERPROFILE%\Pictures\Wallpapers`, then run `.\install.ps1`. The installer replaces the `__WALLPAPERS_PATH__` placeholder because this YASB widget version does not expand `%USERPROFILE%` or `~` in `image_path`.

## Troubleshooting

### Installing Matugen with Cargo

Matugen is distributed as a Rust crate. Installing it with Cargo compiles the Rust binary locally:

```powershell
cargo install matugen
```

On Windows, Rust crate compilation may require the Microsoft C++ build toolchain. If `cargo install matugen` fails with linker errors or reports that `link.exe` or a C++ build tool is missing, install **Visual Studio Build Tools** from the official Microsoft installer.

In the Visual Studio Build Tools installer, select:

- **Desktop development with C++**
- MSVC build tools for the installed architecture
- A Windows 10 or Windows 11 SDK

After installation:

1. Close and reopen PowerShell.
2. Verify Rust and Cargo:

   ```powershell
   rustc --version
   cargo --version
   ```

3. Retry the crate installation:

   ```powershell
   cargo install matugen
   ```

If Matugen was installed successfully but PowerShell cannot find it, verify that the Cargo binary directory is on `PATH`:

```text
%USERPROFILE%\.cargo\bin
```

You can also run the binary directly:

```powershell
& "$env:USERPROFILE\.cargo\bin\matugen.exe" --version
```

The Visual Studio Build Tools are only needed to compile Rust crates locally. They are not required at runtime when using an already-built Matugen binary.
